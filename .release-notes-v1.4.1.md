DevArt Exts 1.4.1 hardens ACL, backup export, and source-block save behaviour for Joomla 6. Safe update from 1.4.0 / 1.3.x. Shortcode syntax unchanged.

### Changed
- Empty `{source}` allowed_groups is fail-closed at save (Super Users / core.admin only)
- Unauthorised savers keep existing `{source}` blocks after editor-safe normalization (entities, whitespace, outer `<p>`); new/modified blocks are stripped
- Backup export streams JSON in chunks (no full in-memory accumulation)
- Snippet save and backup import reject unknown Access view levels (never coerce to Public)
- Editor snippet/code-snippet ajax list endpoints require component manage or content create/edit/edit.own
- Snippets plugin batch-preloads alias/title lookups with collation-safe fallback

### Fixed
- Code snippets assets served from `/media/plg_content_devartcodesnippets/` via WebAssetManager
- TinyMCE/entity rewrites no longer false-strip unchanged stored `{source}` blocks
- Backup import hygiene (20 MB limit, AUTO_INCREMENT after commit, package element lookup)

### Removed
- Dead Social Share admin remnants and Source “Insert empty wrapper” action

### Notes
- Requires Joomla 6.0+ and PHP 8.3+
- Social Share / Open Graph remain in DevArt Article Tools
- Snippet HTML remains trusted-admin content (script strip best-effort); further sanitization planned for 1.4.2
- For very large databases, export snippets and code snippets separately; import limit remains 20 MB
